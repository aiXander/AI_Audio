# AI_Audio — creative hacking on AI audio models

## Mission

A playground for exploring open AI audio models and how they can be **tweaked, hacked and bent to make new kinds of music**: style transfer, latent-space interpolation and morphing, audio-to-audio re-synthesis, codec/autoencoder surgery, LoRA finetunes on custom material, prompt and sampler abuse, chaining models together. The goal is new sounds and new creative workflows, not benchmark scores: a weird result that sounds interesting beats a "correct" one. Nothing here is deployed; it's Xander's research bench on two machines: this M2 Mac (MLX inference, the studio UI) and his NVIDIA GPU box (LoRA training, CUDA-only models), kept in sync through git (**Git** below).

**North star (Xander, 2026-11-08).** The bench serves one goal: an **AI-native Ableton**, a time-based composition studio rebuilt with SA3's diffusion model underneath (the studio, Library, Composer, Arranger and DJ view in `sa3lab/` are its parts). It is built mostly for Xander himself, so he can get really good at playing it and make **about an hour of original music to DJ live over**, in his own performance with projection mapping. It is the sibling of WZRD (`~/Documents/GitHub/Gigabrain/VJ/WZRD`), his AI-native rebuild of Resolume for VJs: the same move, for producers. A weird sound still beats a correct one, but a feature earns its place by getting a finished, playable track closer. What the set needs that doesn't exist yet: [docs/TODO/sa3-one-hour-set.md](docs/TODO/sa3-one-hour-set.md). The why, and the show this feeds, are in Xander's vault (`~/Documents/me`): `realtime_audio/CLAUDE.md` (his music) and `Events/own_performance.md` (the performance).

**This codebase is yours:** how it's built is your call, and you'll keep building on it (the vendored model repos and submodules excepted: change those only as the task needs).

**Current focus: Stable Audio 3 (SA3) and its SAME-L codec.** Unless Xander names another model, assume the task is about SA3 and work from [stable-audio-3/](stable-audio-3/). Its `CLAUDE.md` (runtime, commands, traps) is imported below for Claude; **any other agent: read `stable-audio-3/CLAUDE.md` now.** Its relative paths (`optimized/mlx/sa3`, `docs/…`) resolve under `stable-audio-3/`, not this folder. Any SA3 docs question (paper, MLX install, prompting, LoRA training): start at [stable-audio-3/docs/INDEX.md](stable-audio-3/docs/INDEX.md).

- **Every model download goes into `models/`**, never `~/.cache`, so Xander can reclaim disk by deleting one folder. - **Everything in git is public** (`aiXander/AI_Audio` and both forks): code, config and markdown only. Never commit weights, audio, datasets, renders or secrets (HF tokens, API keys).
- **Never push or open PRs to the original repos** (Stability AI, dadabots) unless Xander asks; his own repo and forks are the only push targets.
- **Paid compute (Modal, APIs) needs a go-ahead** per new job type; a re-run of something already approved is fine.
- **Free to run without asking:** local generations and experiments, tests, reading model cards, papers and HF/GitHub pages.
- **The studio UI is Xander's live workspace, not a test bench.** He is using it most of the time. The server does **not** auto-restart on code edits (Xander turned that off: page reloads mid-session were unbearable), so `sa3lab` edits go live only when he runs `make start`. Never restart or kill the studio yourself; end your summary with "run `make start` to load this". An agent's test render lands in his history, so test in the browser only to chase a real bug, or once at the end of a big sprint; otherwise verify with `node --check`, a Python parse/import, or by reading the code, and tell Xander what to look at.

## Repo layout

- `stable-audio-3/` — submodule, our fork of Stability AI's Stable Audio 3 (text-to-audio/music diffusion + SAME audio codec). Own `CLAUDE.md`.
- `underfit/` — submodule, our fork of `dada-bots/underfit`, the SA3 LoRA-training dashboard (torch on NVIDIA, or drives the MLX trainer on a Mac). Must sit next to `stable-audio-3/`, because it looks for that folder there.
- `models/` — every downloaded or derived model file, so deleting it reclaims all model disk: `hf-cache/` (SA3 MLX weights, squeakfix decoder LoRA), `derived/` for weights we build. `stable-audio-3/optimized/mlx/models/mlx/*` are links into `hf-cache/`; delete `models/` and the runtime re-downloads on next use.
- `audio-data/` — source audio we feed models, as `<artist>/<release>/`. Purchased/copyrighted: gitignored, never commit or share.
- `outputs/` — all generated audio. Gitignored.
- `sa3lab/` — our own SA3 code, outside the upstream clone; runs with the MLX venv. `studio` is upstream's MLX gradio UI re-skinned without touching upstream files, localhost only. The `.json` sidecar next to each render is our **render dataset**: a `gen` block (everything needed to regenerate), a `label` block (0-10 score, tags, `played`, `starred`; trash scores 0, stamps `label.deleted` and moves the clip to `outputs/sa3-gradio/deleted/`, kept as negative training rows; `outputs/starred/` holds symlinks whose labels write through to the original) and an `analysis` block (measured vs prompted BPM). `outputs/sa3-gradio/*.json` is the raw dataset for future scoring models / finetunes; a2a and inpaint inputs are archived in `outputs/sa3-gradio/inputs/`.
- Each model gets its own subfolder (own `CLAUDE.md`) plus a row in the documentation map. A third-party model repo becomes a fork + submodule (procedure below), never a bare clone.

## Load-bearing rules

1. Generated audio goes to `outputs/` with a descriptive filename (model + what the experiment was, e.g. `sa3_styletransfer_jazz-to-techno_s0.6.wav`), so Xander can tell renders apart without opening them.
2. When an experiment works or fails interestingly, record the settings that produced it (prompt, seed, strength, checkpoint) in the research doc's Log — a sound you can't reproduce is lost.
3. Inference on the Mac (MLX) where possible; training and CUDA-only work on the GPU box; Modal only when neither works.
4. Quick functional tests of any render path (does it render, where does the file land, is the sidecar right) use **6 s** clips: Length 6 in the studio, `overrides={"Length": 6.0}` in `sa3lab/anarchy/headless.py`. Never the 120 s default: it costs a minute of GPU per check and competes with Xander's own renders. Long durations are for real listening batches only.
5. To interpret or compare renders (what Xander hears, what a knob changed), look at them: `stable-audio-3/optimized/mlx/.venv/bin/python sa3lab/dadagrid.py <audio or sidecar .json …>` stacks their mono dadaspecs (the studio's spectrogram) into one labeled PNG you open with Read; how to read one is in its docstring. Metrics like onset or loudness correlation come second to looking.
6. Every experiment folder under `outputs/` (an anarchy session, a composer-exp run, a bench) gets a short `context.md`: why we ran it, the settings held fixed, what each block asks, and what we learned (filled in once the renders are judged). The next agent reads those before designing a follow-up.

## Git: submodules and two machines

Each third-party model repo is a **git submodule** pointing at Xander's fork, so both machines run the same modified code.

| Folder | `origin` (push here) | `upstream` (fetch only) |
|---|---|---|
| `.` | `aiXander/AI_Audio` | — |
| `stable-audio-3/` | `aiXander/stable-audio-3` | `Stability-AI/stable-audio-3` |
| `underfit/` | `aiXander/underfit` | `dada-bots/underfit` |

- **Xander's shortcut: `make push m="msg"` / `make pull`** (`scripts/sync.sh`). Push commits *everything* in each submodule then the parent and stages the whole tree, so **agents don't use it** (parallel agents share the tree); agents commit by hand as below, with `git commit --only <paths>`.
- **Commit order: submodule first, then the parent.** Commit and push inside the submodule (to its fork's `main`), then in `AI_Audio` commit the changed submodule folder ("Bump stable-audio-3: <what>") and push. Pushing the parent while it points at an unpushed submodule commit breaks `git pull` on the other machine.
- **Check the branch before committing in a submodule:** `git -C stable-audio-3 branch --show-current`. Empty means a detached HEAD (left by `git clone --recurse-submodules` or `git submodule update`): run `git checkout main && git pull` first. Already committed while detached → `git branch rescue` before switching, then merge it into `main`.
- **Pulling the other machine's work:** `git pull && git submodule foreach 'git checkout main && git pull'`. Plain `git pull --recurse-submodules` also works but leaves submodules detached.
- **Syncing with upstream:** `cd stable-audio-3 && git fetch upstream && git merge upstream/main`, resolve conflicts with our edits, push the fork, bump the pointer in the parent. Keep our edits to upstream files small and one-purpose per commit so these merges stay easy.
- **The parent's `.gitignore` does not apply inside submodules**, and the forks are public too. Write training runs, checkpoints and datasets outside the submodule (`models/`, `audio-data/`, `outputs/`) or under a path the submodule already ignores (underfit's `state/`). Underfit's `.gitignore` ignores `CLAUDE.md`/`AGENTS.md`: `make push` force-adds them; by hand, use `git add -f`.
- **Fresh machine, one-time setup** after cloning: in each submodule run `git checkout main`, `git remote add upstream <original url>`, `git remote set-url --push upstream DISABLED` (the Mac has this; it blocks accidental pushes to Stability or dadabots), and make `origin` pushable (`git remote set-url origin git@github.com:aiXander/<repo>.git`, or `gh auth setup-git` for https). `.gitmodules` uses https URLs so cloning needs no SSH key.
- **Adding a new model repo:** agents can't create the fork (the permission classifier blocks creating public repos). Ask Xander to run `! gh repo fork <owner>/<repo> --clone=false`, then `git submodule add -b main https://github.com/aiXander/<repo>.git <repo>`, set up its remotes as above, add it to this table and the documentation map, and commit `.gitmodules` + the folder together. A repo already cloned here as a plain clone: fork it, repoint `origin` → fork and the original → `upstream`, push, then `git submodule add` with the same path (git adopts the existing checkout).
