SA3 & beyond — exploration plan

AI_Audio research bench · 2026-11-05 · built from the repo, the local reference docs and the ~50-idea backlog in the SAME-L research doc ·

The goal is to make Stable Audio 3 sound like something it was never trained to sound like. Out of the box SA3 is "correct but not compelling": seeds converge on similar melodies and defaults sound like stock music. This plan works outward from cheapest to deepest. First map the knobs we already have, then treat the SAME codec as an instrument on its own, then rewrite the sampler, then train lightly, then add new controls, and finally chain SA3 with other models. Every phase produces sounds, not just infrastructure.

Where the bench is today

What's installed and what it means

  • On disk: Small-Music + SAME-S (30 s clip in ~5 s) and Medium + SAME-L (20 s clip in ~11 s, 3.6 GB peak RAM), plus the T5Gemma text encoder. The local web UI runs at localhost:7860.
  • Not downloaded: Small-SFX and the -base (pre-distillation) checkpoints. See the download decisions at the bottom.
  • Machine: 24 GB unified memory, 76 GB free disk. The reference doc still says 16 GB free, which is out of date, so downloads are no longer the blocker they were.
  • No renders exist yet. AI_Audio/outputs/ doesn't exist, and the first test render listed in the research doc is gone.

The two code facts that shape the plan

  • One hook for every sampler trick. optimized/mlx/scripts/sa3_mlx.py builds a model_fn(x, t) that returns a velocity and passes it to sample_flow_pingpong() in models/defs/sa3_pipeline.py. Our own script can import both and swap in any model_fn, so upstream files are never edited.
  • The MLX DiT only wires inpainting conditioning. SA3's designed slot for new time-varying controls (modular_local_cond, zero-initialised, so it's a no-op until trained) exists only in the PyTorch code. Using it on the Mac means porting it first (Phase 5).

Roadmap

Phases 1 and 2 run in parallel on what's already on disk. The amber tags are download gates: an experiment with a gate waits for that download.

A Small-SFX DiT, 0.9 GB B Medium DiT + SAME-L enc/dec, 6.3 GB C a -base DiT: small 0.9 GB, medium 2.9 GB D stem separator (python-audio-separator / Demucs)

Recommended first session

  1. P0.1–0.3: make outputs/, the sa3lab/ harness and the grid renderer. Everything after this reuses them.
  2. P1.1, the extreme-knob grid, on Small-Music, then score it in the labeling page. This is the cheapest map of the model's weird corners.
  3. P2.3, latent circuit-bending on SAME-S with a track of your own. This tests whether the codec is an instrument in itself.
  4. Say yes to gates A and B. That unlocks cross-model guidance, SAME-L and AudEdit for the next session.

House rules for every experiment

The logging loop

  • Renders go to AI_Audio/outputs/<phase.id>_<name>/. Filenames say model + experiment + key setting, e.g. sm-music_cfg-neg1_noise2.0_s7.wav.
  • Each render gets a .json sidecar with every flag and the seed. A sound you can't reproduce is lost.
  • Score grids in a labeling page (the labeling-ui skill), which writes labels.json. The next round builds on those labels.
  • Keepers and interesting failures go into the research doc's Log as a dated row with their settings.

Code hygiene

  • Our code lives in AI_Audio/sa3lab/, outside the upstream clone. It runs with the MLX venv (stable-audio-3/optimized/mlx/.venv/bin/python) and puts optimized/mlx on sys.path.
  • Upstream files stay read-only, so git pull --ff-only keeps working.
  • Always pass an absolute --out to ./sa3. Relative paths land in optimized/mlx/output/, whatever your cwd.
  • Post-trained DiTs want ping-pong, ~8 steps, CFG 1. The -base DiTs want ~50 Euler steps at CFG ~7. Mixing them up is off-distribution, which can be the point, but should be a deliberate choice.
